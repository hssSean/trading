1. 任務書是通用版本（BingX、策略 A／B／C：趨勢＋均值回歸＋資金費率），**跟這個系統不符**：實際是幣安 testnet 上的 S3-A＋S3-B 真倉（日線唐奇安突破＋分數），加上 S1 模擬帳本。Phase 2～5（回測、樣本外、walk-forward）由研究端 `C:\trading_stratage` 負責，而且已經做過，這裡沒有重做。
2. Phase 1 正確性稽核找到 **4 個會留下沒保護部位，或會誤撤使用者單子的問題**，已修好並補上測試；另外修了 1 個測試設定問題。
3. 還沒解決、要你決定的事項在最後一節，包括主網前的 API 金鑰權限、事件與斷路器要不要做。

## Phase 0：盤點

見 `CLAUDE.md`「專案概觀」、`docs/ARCHITECTURE.md`、`docs/strategy-deploy-2026-10-06.md`，這裡不再重寫。資料流：

正式站日線 → `runPrep`（幣池、廣度、BTC 條件、候選，Redis `s3s1:prep:<X>`）→ live-runner UTC 00:00:30～02:00 → 資金費、止損距離、分數 = 2、A／B 上限 → 市價買進 → STOP_MARKET（全部數量）＋ TAKE_PROFIT_MARKET（A、B 各 1/3，+1R）＋ B 加碼 → 每 15 秒管理 → 部位歸零後依成交紀錄分帳。

部位大小 `sizePosition`：Q = floor(權益 × f ÷ (E − SL), step)。手算：權益 4826.17、f 4%、E 0.2721、SL 0.23776 → 193.05 ÷ 0.03434 = 5621.7 → **5621**（`tests/s3aLive.test.ts` 有這個案例）。

### 已修（每項都有測試）

1. **市價進場送單丟錯、但其實已經成交 → 留下沒人管的裸倉**（`src/engine/s3aLive.ts` `confirmEntry`）。以前送單逾時（axios 10 秒）會被當成「下單失敗」；送單成功但第一次查持倉還沒看到，也會直接略過。兩種情況都會讓交易所上有一個沒有止損、S3 也不認得的部位，而且隔天 S3 會把它當成「別的策略的持倉」跳過。現在不管送單成功或丟錯都重查 3 次，查到就接手（存檔＋掛止損止盈）。測試：`tests/s3aEntryConfirm.test.ts`。
2. **止盈單或 S3-B 的加碼單被誤認成止損**（`src/engine/watchdog.ts`）。全帳戶對帳把任何 STOP_MARKET／TAKE_PROFIT_MARKET 都當成保護，不看方向。現在只承認「平倉方向」的止損類條件單（多單要 SELL STOP）。
3. **手機 App 手動掛的條件進場單會被自動撤掉**。「沒有持倉的條件單」原本一律撤；現在只撤 reduceOnly／closePosition 或 `s3a-` 開頭的單，其他的只記 log。
4. **帳戶設定由程式驗證**：設逐倉時只接受 -4046（已經是逐倉），其他錯誤會中止這筆進場，不會用全倉繼續；啟動時讀持倉模式，是雙向持倉就推播。
5. 有倉沒止損以前只記 log，現在會推播（同一個幣 6 小時一次）。
6. `vitest.config.ts` 排除 `.claude/**`：Claude Code 的舊 worktree 副本原本會被一起跑。

驗證：`npx tsc --noEmit` 0 錯誤；`npx vitest run` 450 個測試全過；`npx next build` 0 錯誤。

由研究端負責，而且已經完成：2020-03～2026-08 全市場回測，含已下市幣（處理倖存者偏誤）、手續費＋滑價＋資金費；驗收用參考交易逐筆比對，誤差 1e-6（`npm run s3s1-acceptance`）。對照任務書：

- **回測與實盤一致性（6.4）**：研究端每日前向對帳（`s3_xcheck.py`），有不一致會推播。
- **樣本量**：S3 每月約 2 筆，任務書上線閘門「≥ 200 筆樣本外」要很多年才達得到。主網閘門已經另外預先登記（`C:\trading_stratage\docs\轉實盤條件_預先登記.md`）。

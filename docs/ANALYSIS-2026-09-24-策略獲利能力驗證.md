# 2026-09-24 策略獲利能力驗證：扣成本後每筆 −0.055R，顯著為負

> 工具：`npm run verify-strategy [月數] [幣數]`（`scripts/verify-strategy.ts`）。
> 先驗量測工具、再模擬、再對照真實成交。**調參前先讀這份與 08-30 那份。**

## TL;DR

| 項目 | 結果 |
|---|---|
| 模擬範圍 | 12 個月 × 今日成交量前 15 檔，1H 進場，n=2079 |
| 毛 R（未扣成本） | 每筆 +0.022R，t=+1.00，95%CI [−0.022, +0.067] |
| **淨 R（扣手續費、滑價、資金費率）** | **每筆 −0.055R，t=−2.40，95%CI [−0.100, −0.010]** |
| 樂觀上界（剔除「成交那根就打止損」104 筆） | 每筆 +0.003R，CI [−0.043, +0.050] |
| 策略 A | −0.033R，t=−1.44（不顯著） |
| **策略 B** | **−0.514R，t=−4.34，n=93（顯著為負）** |
| 真實成交（90 天，n=134，未扣手續費） | −0.131R，t=−1.35 |

**結論：這套策略目前不能賺錢。** 訊號本身的毛邊際接近 0（最好的情況是 +0.02R），
而成本每筆吃掉 0.077R——止損距離中位數 1.78%，一趟來回的手續費＋滑價約 0.14%，
等於每筆固定付 ~8% 的 R。毛邊際小於成本，扣完就是負的。前後半段都是負、
12 個月只有 4 個月為正、15 檔只有 5 檔為正，不是某一段行情造成的。

模擬的悲觀假設（成交那根同時碰到止損判止損）占了大部分差距：真相介於
−0.055R 與 +0.003R 之間。**即使取最樂觀那端，也只是打平，沒有任何證據能賺錢。**
這跟 08-25 三層量測、08-30 真實成交的結論一致，這次是第一個顯著的結果。

## 一、驗證過程中找到的錯誤（已全部修復）

### 線上程式碼

| ID | 問題 | 影響 |
|---|---|---|
| **L1** 🔴 | `generateSignals` 吃形成中 K 棒，而 `signalCache` 以該 K 棒 openTime 為 key → 每小時第一次掃描（K 棒才開幾分鐘）的訊號被沿用整小時 | 真實 1H 資料 **42.4%** 的時點「開盤 3 分鐘」與「收盤前」訊號不同；其中 47/399 是收盤才成立、線上永遠看不到的訊號。線上跑的是「用幾乎空白的 K 棒判斷」的策略，所有回測量的是另一個 |
| **L2** 🟡 | 4H ADX 同樣含形成中 K 棒且被 `regimeCache` 快取 4 小時 | 3.2% 時點 regime 落在不同區間 |

修法：`signalCache.closedCandlesOnly()`，route.ts 的訊號與 regime 只吃已收盤 K 棒
（抓 201 根，丟掉形成中那根剩 200）。HTF bias 與 BTC 大盤仍用現價，那兩個本來
就每輪重算、沒有快取問題。**訊號改在 K 棒收盤後的第一次掃描成立。**

> 注意：這修正讓線上行為**對齊**被驗證的策略，但被驗證的策略本身是負的——
> 這個修正不會讓系統賺錢，只是讓「量到的」與「跑的」是同一個東西。

### 回測工具（`backtest.ts`、`exit-compare.ts` 及依賴它們的腳本）

| ID | 問題 |
|---|---|
| B2 🔴 | exit-compare 掛單等 8 根，線上 4 根（註解引用的是只用來抓 K 線的 `WAITING_EXPIRY_HOURS`） |
| B3 🔴 | regime 用 ADX >25/<20 無遲滯，線上 ≥23/≤18 加遲滯 |
| B4 🔴 | `generateSignals` 傳 `htfBias=null`，線上傳 4H EMA200 方向；也沒有 confluence 關卡 |
| B5 🔴 | `npm run backtest` 碰 TP1 全平、同根判 TP1 贏，沒有部分停利／保本／移動止損／停滯／到期，也不是限價掛單 |
| B6 🔴 | exit-compare／stop-distance-compare／entry-compare 出場從「成交的下一根」開始，成交那根的止損被忽略（系統性樂觀） |
| B7 🟡 | 沒模擬「成交前先碰 TP1 → 取消」 |
| B8 🟡 | exit-compare 的 R 未扣成本 |
| B9 🟡 | 從 1H 拼 4H 以陣列長度對齊，不在 UTC 4H 邊界 |
| B10 🟡 | 「540 根 4H」實際只切 540 根 1H（=135 根 4H） |

修法：新增 `scripts/lib/liveReplica.ts` 作為**唯一一份**線上規則重現（regime 遲滯、
UTC 4H、HTF bias、掛單成交、成交根止損、成本模型），backtest／exit-compare／
verify-strategy 共用；`verify-strategy.ts` 第一階段會比對常數與 route.ts 是否一致，
下次分岔會直接被列出來。

**過去 exit-compare／entry-compare／stop-distance-compare 的結論是在 B2–B10 下跑的**，
方向上都偏樂觀。那些結論是「分不出差異」，偏誤不太可能翻轉它們，但絕對數字不要再引用。

## 二、驗證方法的限制

- 幣種用今日成交量前 15 名回頭測（倖存者偏誤，偏向高估）。
- 只模擬 1H 進場時框；沒有 15m 短線單與多時框 confluence。
- 沒有組合層級風控（熔斷、回撤停機、同向上限、總風險 5%）——模擬每天 ~5.7 筆，
  線上實際 ~1.5 筆。這些關卡只會少做幾筆，不會讓沒邊際的訊號變有邊際。
- 同根 K 線 TP/SL 都碰到判 SL（悲觀）；上面的「樂觀上界」列出了這個假設的影響。

## 三、如果要繼續

1. **策略 B 應該先停掉**：n=93、t=−4.34，是整份報告唯一強烈顯著的分組
   （真實成交的策略別拆解尚未做，要先用真實資料確認再動）。
2. 整體要翻正，毛邊際得先大於成本（每筆 ~0.08R）。在「止損距離 ~1.8%」這個
   尺度上，任何出場微調都救不回來（05 個參數家族都已測過無效）。能動的是
   **進場訊號本身**或**持倉時間尺度**（更寬的止損 → 成本占 R 比例變小）。
3. 不要用這份數據去挑「看起來最好的幣」或「最好的月份」——那是在雜訊上擬合。

# S/R 阻力位不帶資訊——TP1 那段死掉的夾持不用救

> 2026-09-07。起因是使用者問「進場只用 1h，那止盈止損也只看 1h 嗎」，
> 追下去挖出 `buildSignalLevels` 有一段對 1h/4h/1d 恆等於無作用的程式碼。
> 重跑指令：`ENV_FILE=env.txt npx tsx scripts/sr-mechanism.ts`

## TL;DR

| 問題 | 結論 |
|---|---|
| swing 分支的「TP1 被最近阻力夾住」有作用嗎 | **沒有，是死碼**。`tp1Max` 與 `MIN_RR_SWING` 同為 2.0R，`max(min(阻力,2R),2R) ≡ 2R` |
| 而且它影響多少單 | 系統 **98%** 的單是 1h（397/406），全部走 swing 分支 |
| 讓它活過來會比較好嗎 | **不會**。阻力位測不出資訊量，三個指標 p = 0.74 / 0.20 / 0.14 |
| 那「TP1 夾到阻力觸及率 36.4% vs 2R 的 20.8%」呢 | **陷阱**。純粹是目標變近的機械效果，隨機阻力做得到同樣的事 |
| 該做什麼 | **什麼都不做**。不用跑 6 個月走K線模擬，這個變體等同已測過的「TP1 拉近到 +1.0R」 |

**第五個參數家族也關掉了**（前四個見 `docs/TODO.md` 2026-09-03）。

## 1. 起因：一段恆等於無作用的夾持

`src/analysis/signals.ts` 的 `buildSignalLevels`（LONG 分支）：

```ts
const tp1Max = intraday ? entry + risk * 1.5 : entry + risk * 2.0;
const tp1Raw = tpClampPrice !== null ? Math.min(tpClampPrice, tp1Max) : tp1Max;
const tp1    = Math.max(tp1Raw, entry + risk * minRr);
```

`minRr` 來自呼叫端：

```ts
const MIN_RR = intraday ? MIN_RR_INTRADAY /* 1.2 */ : MIN_RR_SWING /* 2.0 */;
```

`isIntradayTF()` 只認 `5m`/`15m`，所以 **1h 走 swing 分支**：上限 `2.0R`、地板
`2.0R`。`tp1Raw ≤ 2R` 恆成立，於是

```
tp1 = max(min(阻力, 2R), 2R) ≡ 2R
```

**「用最近阻力夾住 TP1」對 1h/4h/1d 從來沒有生效過。** 只有 5m/15m 有活的
窗口（1.2R 地板 vs 1.5R 上限），而系統實際上不從那兩個時框進場。

DB 佐證：策略 A 已平倉單 n=122，TP1 距離中位 **2.00R**。

---

## 2. 為什麼這不等於「TP1 該不該拉近」

很容易把「讓夾持活過來」讀成「把 TP1 拉近」，那樣就會直接撞上 2026-09-03
已經結案的東西：

```
TP1 拉近 +1.0R / +1.5R、推遠 +2.5R、TP2 拉近 …  共 6 個變體
最好的一個（TP1 +2.5R）  n=705  每筆 +0.014R  t=2.13
Bonferroni 門檻 |t| ≈ 2.94  →  不過關，雜訊
```

差別在於：那 6 個變體是**對所有單套同一個固定 R 倍數**；阻力夾持是**逐單依
結構決定**。後者只有在「阻力位真的預測價格會停在哪」時才會贏。

所以要測的不是「近一點好不好」，是**阻力位帶不帶這筆單專屬的資訊**。

---

## 3. 方法：置換檢定，不是走K線模擬

走K線模擬要 6 個月 × 15 幣、十幾分鐘，而且結果會把「結構有用」跟「目標變近」
混在一起，分不出是哪個在起作用。

改成直接問機制。對每筆已成交的 1h 單，用 `opened_at`（訊號時間）往回抓 200 根
1h K 線（跟 `route.ts` 產訊號的窗口一致），跑 `findSRLevels`，取當時的最近阻力
（SHORT 取支撐），跟該筆的 MFE（浮盈最高點）比：

```
d = mfeR − resistanceR
  d < 0   價格沒走到阻力就回頭
  d ≈ 0   停在阻力  ← 屏障訊號
  d > 0   直接穿過，阻力沒作用
```

**對照組用置換**：把 `resistanceR` 在交易之間洗牌，破壞「這筆的阻力 ↔ 這筆的
走勢」之間的配對，兩邊的邊際分布完全不動。真實值若跟洗牌後沒差別，代表阻力
不帶資訊。洗 3000 次。

樣本：134 筆 1h 已成交且有 MFE 紀錄 → **85 筆可用**（另 49 筆那個方向根本
找不到 S/R 位，`tpClampPrice = null`，TP1 直接 2R）。

> 那 49 筆本身就是一個發現：**超過三分之一的訊號連夾持的輸入都沒有**，
> 那段程式碼對它們是雙重死碼。

---

## 4. 結果

### 4.1 覆蓋率很高——不是「假 n」那種形狀

```
會被夾到（阻力 < 2R）  77/85 = 90.6%
阻力 ≥2R（夾不到）      8
被夾到的阻力位置(R)     min=0.02  中位=1.16  max=1.90
```

事前擔心的「覆蓋率太低、統計被稀釋」（`ANALYSIS-2026-09-07-止損距離下限.md`
記過那個陷阱）**在這裡不成立**。90.6% 是真的有在動的。

### 4.2 但分布形狀不像屏障

```
d < −0.5       35 筆 (41%)   離阻力還很遠就回頭
−0.5 ≤ d < 0   21 筆 (25%)   逼近但沒到
0 ≤ d < 0.5     8 筆 (9.4%)  停在阻力  ← 最小的一格
d ≥ 0.5        21 筆 (25%)   直接穿過
```

如果阻力是真的屏障，`[0, 0.5)` 應該**過度集中**。它是四格裡最小的，而且
25% 的單直接穿過去。

### 4.3 置換檢定三個指標全不顯著

```
                     真實      洗牌均值    p
觸及率 P(MFE≥阻力)   34.1%     35.3%     0.7358
停在阻力 ±0.5R       34.1%     30.0%     0.2013
corr(阻力R, MFE R)   0.114     0.000     0.1420
```

**觸及率真實值比隨機還低**——方向就錯了。最強的相關性 p=0.14，離任何門檻
都很遠。

> 置換是隨機抽樣，重跑 p 值會在小數第二位跳動（實測第二次跑是
> 0.7388／0.1839／0.1529）。跳動範圍遠小於「離顯著有多遠」，結論不受影響。

### 4.4 那個看起來很香的數字是陷阱

```
TP1 夾到阻力 → 觸及率 36.4%（中位阻力 1.16R）
TP1 維持 2R  → 觸及率 20.8%
```

差 15.6 個百分點，看起來像重大發現。**它純粹是「目標從 2.0R 挪到 1.16R」的
機械效果**——4.3 節已經證明隨機給一個阻力位也做得到同樣的事（35.3%）。

也就是說，「用阻力夾 TP1」實際上只是「把 TP1 挪到 ~1.16R」的迂迴寫法，
而那個已經在 n=705 測過了。

---

## 5. 結論

**不要跑那個 6 個月走K線模擬。** 前置檢查達成目的：這個變體跟已測過的
「TP1 拉近」是同一件事，多跑一次只會多一個 |t|<2。

那段死碼**留著或清掉都行，對績效都是 0**。清掉的唯一理由是少一個會誤導
後人的東西——它讀起來像「我們有用結構位管理 TP」，實際上沒有。

### 但書（不要假裝這是定論）

n=85 不大，p=0.14 是「這裡測不到」而不是「證明為零」。要靠這個翻案，得先
解釋為什麼**決策相關的那個指標（觸及率）真實值低於隨機**。

另外這批 MFE 只涵蓋已成交單。從未成交的那 224 筆（見 §6）沒有 MFE，
所以這份報告說的是「已經進場之後阻力有沒有用」，不是「阻力對訊號品質有沒有用」。

## 6. 順帶記錄：1h 落在 intraday/swing 分界的錯邊（**未量測**）

追這件事的過程中撈出來的，跟上面的結論獨立，**沒有做任何統計檢定**，
記下來避免下次重挖。

`isIntradayTF()` 是二分法，但實際上有三種行為需求，而 1h（98% 的單）
在「價位計算」跟「時間預算」拿到了不一致的待遇：

| | 5m/15m | **1h** | 4h/1d |
|---|---|---|---|
| MIN_RR | 1.2 | **2.0** | 2.0 |
| 止損距離下限 | 0.4% | **1.0%** | 1.0% |
| ATR 倍數 | 1.0–2.0× | **1.5–2.5×** | 1.5–2.5× |
| 止損距離上限 | 5% | **12%** | 12% |
| 需 K 線型態確認 | 要 | **不用** | 不用 |
| 結構 ranging 擋單 | 擋 | **不擋** | 不擋 |
| 到期強平 | 24h | **24h** | 72h／168h |
| 停滯止損 | 8 根 = 40/120 分 | **8 根 = 8h** | 8 根 = 32h／8天 |

**價位是波段規格，碼表是日內規格。**

相關實測數據（1h、406 筆已平倉裡的 397 筆）：

```
從未成交              224/397 = 56%
  其中 cancel_tp1_direct 30 筆：價格直奔 TP1，從沒回頭碰進場價

已成交 173 筆，134 筆有 MFE：
  MFE 中位            0.59R
  曾達 1.0R           33.6%
  曾達 2.0R           18.7%   ← TP1 就掛在這
  持倉中位            5.7h    (p75 8.5h ← 停滯閘在 8h)

  time_stop_stall     n=32  MFE中位 0.61R  實現 +0.067
  pre_tp1_breakeven   n=28  MFE中位 0.61R  實現 −0.061
  stop_loss           n=42  MFE中位 0.08R  實現 −1.046
  trailing_stop       n=20  MFE中位 2.38R  實現 +1.024
  tp2                 n= 9  MFE中位 2.88R  實現 +2.116
```

⚠ **不要拿「只有 18.7% 摸得到 2R」去推 TP1 該拉近**——那是只算好處不算代價的
MFE 反事實試算，`src/lib/exitPolicy.ts` 檔頭專門警告過，而且真的走K線測完是
雜訊（§2）。止損那 42 筆 MFE 中位 0.08R，代表**止損是對的，不是漏水點**。

這張表裡真正沒被量過的是**進場時框本身**：4h 只有 9 筆，5m/15m 從沒當過
進場時框，樣本是 0。要測的話成本不低——`scripts/exit-compare.ts` 的
`collectEntries()` 寫死 `'1h'`，要參數化 + 抓 15m K 線（資料量 4 倍）+ 調
`WARMUP`/`FORWARD_BARS`/冷卻根數，而且會連動 confluence 的票數算法。

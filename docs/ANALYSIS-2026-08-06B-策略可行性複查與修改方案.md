# 策略可行性複查 + 修改方案（提案，尚未實作）

> 日期：2026-08-06
> 資料：`trades-2026-08-06.csv`（140 列訊號，其中 61 筆真正成交並結算）
> 觸發：使用者回報「最近報幾單就止損幾單」
> **狀態：全部是提案，一行程式都還沒改。**

---

## 一句話

**策略沒有崩壞，但也從來沒被證明過。** 真正壞掉的是**訊號量與成交率**——
8/1 起訊號量從每天 3 筆暴增到 12–26 筆，而成交率從 100% 崩到 12–43%，
**56.4%（79/140）的推薦單根本沒成交**。使用者感受到的「一直在虧」，
主要是被大量沒成交的通知稀釋掉了那幾筆賺錢的單。

## 〇、先講一個我自己犯的錯（以及一個真的 bug）

我第一輪分析得出「A級 +0.656R、B級 −0.034R、t=2.48 顯著」，
**這個結論是錯的**，因為匯出程式有 bug：

```ts
// src/app/trades/page.tsx:924
const tier = (r.tier as string | null) ?? 'A';   // ← NULL 一律當成 A級
```

`tier` 欄位是 v2.1 才加的，7 月的舊資料列全是 NULL，**全部被誤標成 A級**。
比對 `分析依據` 欄位裡的「🅱 B級輕倉訊號」標記後，**27 筆被誤標**，
其中包含 AKEUSDT +3.50R、1000SHIBUSDT +3.50R 這兩筆最大贏家——
它們實際上是 B級，卻被算進 A級。

修正後的真實數字：

| 真實 tier | 筆數 | 平均R | 扣成本 | 95%CI（扣成本） | Bootstrap 勝過成本 |
|---|---|---|---|---|---|
| A級 | **5** | +0.972 | +0.832 | [−0.136, +1.800] | 98.4% |
| B級 | **44** | +0.215 | +0.075 | [−0.283, +0.434] | 64.6% |
| 無法判定（tier=NULL） | 12 | +0.472 | +0.332 | [−0.154, +0.817] | — |

A vs B 差異 t = **1.44**（要 >2 才算顯著）——**不顯著**。
真實 A級只有 5 筆，任何「只做 A級」的結論都是在 5 個樣本上做決定。

**這件事的教訓不是「A級沒有比較好」，是「我們目前根本沒有能力判斷」。**
所以下面的方法 0 必須先做。

## 二、真正壞掉的東西：成交率

### 成交率崩塌的時間點非常明確

| 日期 | 訊號數 | 成交 | 成交率 |
|---|---|---|---|
| 7/16 – 7/28 | 每天 1–6 | 全部 | **100%** |
| 7/29 | 5 | 2 | 40% |
| **8/1** | **26** | 3 | **12%** |
| 8/2 | 23 | 5 | 22% |
| 8/3 | 23 | 9 | 39% |
| 8/4 | 7 | 3 | 43% |
| 8/5 | 9 | 3 | 33% |
| 8/6 | 12 | 2 | 17% |

7/31 修掉 `same_dir_cap` 的 bug 之後（原本擋死全部訊號），訊號量從每天 3 筆
變成 26 筆——**但多出來的訊號幾乎都掛不到**。

### 未成交的組成

| 原因 | 筆數 |
|---|---|
| 掛單逾期未成交（4 根 K 線） | 46 |
| **直達TP1未成交** | **27** |
| 行情走遠未成交 | 6 |
| **合計** | **79 / 140 = 56.4%** |

### 機制找到了：掛單掛太遠

用 8/4 新增的 `進場距離(ATR)` 量測（目前只有 21 筆有資料）：

| | 筆數 | 進場距離(ATR) 平均 |
|---|---|---|
| 有成交 | 5 | **1.06** |
| 沒成交 | 16 | **2.27** |

沒成交的單，掛單價距離當下市價是成交組的 **2 倍以上**。
明細看得更清楚——沒成交那組有 3.61 / 4.80 / 3.34 / 3.38 / 3.10 這種
距離 3–5 個 ATR 的掛單，那等於在要求市場回頭走一大段才進場。

樣本只有 21 筆，但方向毫不含糊：**成交組全部 ≤2.04，沒成交組大多 ≥1.26。**

### 代價有多大（上限估計）

27 筆「直達TP1未成交」= 價格根本沒回到掛單價，直接衝到 TP1。
若這些單在掛單價成交並走到 TP1，平均 **+2.00R**，27 筆合計 **約 +54R**。

**對比：整段期間真正落袋的總R 只有 +20R。**

⚠️ **54R 是理論上限，不是可取得的數字。** 真的改成市價進場的話：
進場價變差、R 縮水，而且有些單市價進場後會直接吃止損。
**真正的答案在 `cancelShadow`**（8/1 建的影子模擬，資料在 Redis，
`/api/reject-funnel` 的 `cancelStats`，App 的「體檢」頁看得到）——
那裡記的是「用 signal_price 市價進場實際模擬到底的淨R」。

**沒有那個數字之前，不要動進場邏輯。** 這是本專案自己的紀律。

## 三、其他發現

### 虧損單不是「回吐」，是「一進場就錯」

11 筆有 MFE 資料的虧損單，最高浮盈幾乎都是 0：

```
ZECUSDT   MFE +0.16  →  −1.00
PUMPUSDT  MFE +0.11  →  −1.00
HYPEUSDT  MFE −0.02  →  −1.00
ZECUSDT   MFE −1.06  →  −1.00   ← 從沒有過任何浮盈
COTIUSDT  MFE −0.65  →  −1.00   ← 同上
```

這代表虧損單**不是**被止損掃到才輸的，是進場方向本身就錯。
「把止損拉寬」救不了這種單，只會輸更多。

### 同幣種重複洗版

最近 40 筆訊號：ADAUSDT **10 次**、ZECUSDT **7 次**、BNBUSDT 4 次。
掛單沒成交被取消 → 鎖定解除 → 下一輪同一個幣又符合條件 → 再發一次。
這是體感「一直在報單」的直接來源，也吃掉 Vercel CPU 額度。

### 幣種表現（n≥3，僅供觀察，不足以下結論）

| 幣種 | 筆數 | 總R |
|---|---|---|
| BTCUSDT | 10 | +5.53 |
| SOLUSDT | 6 | +2.80 |
| ETHUSDT | 5 | −1.37 |
| ZECUSDT | 9 | **−1.57** |
| GIGGLEUSDT | 3 | −1.45 |

ZECUSDT 9 筆 −1.57R，而且它同時是重複洗版第二名。樣本仍不足以拉黑名單。

### 時間止損：擋得對，不要動

14 筆，平均 +0.064R——不賺不賠。影子模擬先前已證明「不砍會更糟」。
**淨R ≥ 0 的關卡不要動**，符合既有紀律。

### 止損永遠剛好 −1.00R

8 筆原始止損，全部精準 −1.00R，代表紀錄假設成交在止損價、零滑價。
MAE 資料顯示實際有單走到 −1.33R。**自動化之前這個必須修**，
否則所有統計都建立在樂觀假設上。

## 四、提案（依「該不該現在做」排序，不是難度）

### 方法 0 — 修 tier 匯出 bug ⚠️ 必做，且不算策略改動

`page.tsx:924` 的 `?? 'A'` 改成不預設（空字串或 `'?'`）。

- **理由**：這不是調參，是修量測。現在任何跟 tier 有關的判斷都不可信，
  我自己就被騙過一次。
- **風險**：零。只影響匯出顯示。
- **代價**：舊資料無法回溯（tier 在 DB 就是 NULL），但至少不會再假裝知道。

---

### 方法 1 — 掛單距離上限濾網 ★ 最高價值

**加一個關卡：掛單價距離現價超過 N×ATR 就不發訊號。**

- **證據**：成交組 1.06 ATR vs 未成交組 2.27 ATR，差 2 倍以上。
- **為什麼選這個而不是「改進場價計算」**：
  這只是**加一個濾網**，不動 `longEntry`/`shortEntry` 的計算方式，
  符合「一次只動一個濾網」。改進場價公式會同時動到 entry / SL / TP1 / TP2
  四個數字，出事分不清是哪個造成的。
- **N 取多少**：資料建議 1.5–2.0 之間，但**這正是需要影子模擬數據的地方**。
- **前置條件**：**先去 App 的「體檢」頁看 `cancelStats` 的淨R**。
  - 若 `cancel_tp1_direct` / `cancel_ran_away` 的淨R **明顯 > 0**
    → 代表「等回調」確實在錯過賺錢的單，值得收窄距離
  - 若淨R **≤ 0 或接近 0** → 代表等回調是對的，那些單就算進場也不賺，
    **不要動**，改去做方法 2
- **預期效果**：訊號量下降（少發那些注定掛不到的），成交率上升，
  通知量回到可讀範圍。**不保證提升期望值**——它修的是「機會被浪費」，
  不是「訊號品質」。

---

### 方法 2 — 同幣種訊號節流

同一個幣種在 N 小時內只發一次訊號（不論前一次有沒有成交）。

- **證據**：ADAUSDT 10 次、ZECUSDT 7 次 / 40 筆訊號。
- **價值**：主要是體驗與 CPU，**不直接改善期望值**。
- **風險**：低，但會漏掉「第一次沒掛到、第二次剛好對」的單。
- **建議**：跟方法 1 一起評估——如果方法 1 讓訊號量掉一半，
  這一項可能就不需要了。**不要同時做兩個。**

---

### 方法 3 — 實際成交價回寫 ⚠️ 自動化前必做

現在假設成交在掛單價、止損成交在止損價，零滑價。

- **證據**：8 筆止損全部剛好 −1.00R，但 MAE 顯示實際有走到 −1.33R。
- **為什麼重要**：扣成本後平均只有 +0.183R。若真實滑價平均 0.05R，
  61 筆就是 3R 的系統性高估——足以把「勉強正期望」變成「零」。
- **這不是策略優化，是讓帳目誠實。** 沒有這個，自動化後的所有數據都不可信。

---

### 方法 4 — A/B 級門檻 🔬 資料不足，先不要動

真實 A級只有 5 筆。B級 44 筆扣成本 +0.075R，貼在成本線上。
- t = 1.44，不顯著。
- **做完方法 0 之後重新累積 2–3 週**，才有辦法判斷。
- 現在動 = 在 5 個樣本上做決定。

---

### 不要動的東西

| 項目 | 理由 |
|---|---|
| 時間止損 8 根 K 線 | 14 筆平均 +0.064R，影子模擬證明砍是對的。淨R ≥ 0 不要動 |
| 止損距離 | 虧損單 MFE 幾乎都是 0，是方向錯不是被掃。拉寬只會輸更多 |
| TP2 = 3.5R | 3 筆 TP2 貢獻 +6.73R，是主要獲利來源。砍上限等於砍厚尾 |
| 幣種黑名單 | ZECUSDT 9 筆 −1.57R 看起來差，但樣本不足 |

## 五、建議執行順序

```
1. 方法 0（修 tier 匯出）          ← 現在就能做，零風險
2. 去體檢頁看 cancelStats 淨R      ← 你來看，這決定第 3 步做不做
3. 方法 1 或 方法 2（二選一）      ← 依第 2 步的數據決定
4. 觀察 1–2 週                     ← 一次只動一個，要看得出效果
5. 方法 3（成交價回寫）            ← 自動化之前一定要做完
6. 回到自動化（testnet 對帳）
```

## 必須說清楚的前提

**這份分析沒有任何一項能保證提升盈虧率。**

整體期望值扣成本後 95% 信賴區間仍然跨 0（[−0.101, +0.467]），
跟 8/4、8/5 兩次體檢的結論一模一樣——**策略是否真的有正期望值，
到今天仍然在統計上未被證明。**

方法 1 修的是「機會被浪費」（56% 沒成交），方法 3 修的是「帳目不誠實」，
兩者都不會把一個未被證明有優勢的策略變成有優勢的策略。

**要不要繼續投入、要不要投真錢，是你的決定，這份分析不構成投資建議。**

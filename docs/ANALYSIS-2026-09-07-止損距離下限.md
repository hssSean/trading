# 止損距離沒有下限——測完了，結論分兩層

> 2026-09-07。起因是當天 00:05 那筆 BTC：38 秒虧掉當日虧損上限的 71.6%。
> 重跑指令：`npx tsx scripts/stop-distance-compare.ts 6 15`

## TL;DR

| 問題 | 結論 |
|---|---|
| 策略 B 的止損距離沒有下限 | 是事實，程式碼確認 |
| 止損太近會讓手續費占 R 暴增 | **是算術，不需要樣本**。0.103% 止損 → 手續費 0.58R |
| 加最小止損距離下限會比較好嗎 | **測不出來**。8 個變體全部 \|t\| < 1，符號還混雜 |
| 那還有什麼問題 | **有，而且是另一個東西**：倉位公式在止損距離小時會繞過「每筆本金 20% 帳戶」的設計，單筆最高吃掉 97% 帳戶保證金 |

**不要因為這份報告去加止損距離下限。** 要處理的是最後那一項，它跟策略參數無關。

## 1. 起因

2026-09-07 00:05 的 BTC 空單，38 秒內走完進場到止損：

```
00:05:32  LIMIT SELL  0.2462 BTC @ 80289.10     名目 19,767 USDT
00:06:10  MARKET BUY  0.2462 BTC @ 80383.56     reduceOnly，止損觸發
實現損益 -23.26 USDT   手續費 -11.87 USDT   合計 -35.79 USDT
```

當日虧損上限 50 USDT，這一筆吃掉 71.6%，手續費占虧損總額 34%。

DB 欄位顯示止損距離 **0.103%**。

## 2. 兩條路徑不一致

策略 A 的止損緩衝有硬下限（`signals.ts:577`）：

```ts
const slBuffer = Math.min(
  intraday ? Math.max(atrVal * atrMulti, price * 0.004)
           : Math.max(atrVal * atrMulti, price * 0.010),
  price * MAX_SL_PCT,
);
```

`isIntradayTF()` 只認 5m/15m，**所有單都跑 1h，所以走的是 swing 分支，下限 1.0%**。
DB 實測策略 A 的最小止損距離是 0.987% / 0.993% / 1.000%，完全吻合。

策略 B 沒有這道。它的止損是「較近者勝」（`signals.ts:899` / `948`）：

```ts
LONG   sl = Math.max(entry - atrVal, bb.lower - atrVal * 0.5)
SHORT  sl = Math.min(entry + atrVal, bb.upper + atrVal * 0.5)
```

價格從布林軌外側收回來時 `bb.upper` / `bb.lower` 會很靠近 entry，止損距離因此可以
任意小。實測 13 筆真倉策略 B，**12 筆止損距離 < 1.0%**，最極端 0.103%。

這看起來不像刻意的設計選擇，比較像策略 A 加下限時漏掉了 B——跟 2026-07-24
只給均值回歸做空加放量門檻、做多漏掉是同一種形狀。

## 3. 手續費那部分是算術，不要拿統計去證

倉位照固定風險金額反推（`position.ts:47`）：

```
名目 = riskUSDT / 止損距離
```

手續費按名目收，所以換算成 R：

```
手續費(R) = 往返費率% / 止損距離%
```

實測費率 0.060%（那筆 BTC：11.87 / 19,767。進場 LIMIT maker 0.02% + 止損
MARKET taker 0.04%）：

| 止損距離 | 手續費(R) |
|---|---|
| 0.103% | **0.58R** |
| 0.25% | 0.24R |
| 0.50% | 0.12R |
| 1.00% | 0.06R |
| 2.00% | 0.03R |

**這是除法，不需要樣本。** 止損距離 0.103% 的單在開倉瞬間就背 0.58R 的確定成本。

## 4. 但「成本高」不等於「加下限比較好」

下限有代價，而且是兩層：

- 止損推遠 → R 的分母變大 → 同一段價格波動換到的 R 變小
- 策略 B 的 TP 固定在布林中軌，止損推遠 → `rr` 下降 → 低於 `MIN_RR_B = 1.5`
  就**整個訊號不發**

好處與代價只能實測。`scripts/stop-distance-compare.ts` 測了兩種修法各四個門檻：

- **clamp** — 把止損推遠到下限（訊號照發，風險距離變大）
- **skip** — 止損距離低於下限就不發（不扭曲止損位置，純過濾）

配對方式跟 `entry-compare` 一樣，**以訊號為單位**：不同下限產生不同的訊號集合，
用「交易」配對就是在比不同的東西。沒發／沒成交記 0R。手續費已扣。

### 小樣本說有效，大樣本推翻

```
3 個月 × 8 檔（受影響訊號 ~17）
  skip <1.0%    每筆差 +0.026R   t= 2.59   ★
  skip <0.8%    每筆差 +0.025R   t= 2.55   ★
  clamp ≥1.0%   每筆差 +0.022R   t= 2.37   ★
  （8 個變體全部為正，5 個 t > 2）

6 個月 × 15 檔（受影響訊號 22–77）
  skip <0.4%    每筆差 +0.061R   t= 0.57
  clamp ≥0.6%   每筆差 +0.013R   t= 0.14
  skip <1.0%    每筆差 -0.003R   t=-0.02   ← 小樣本這個 t=2.59
  clamp ≥1.0%   每筆差 -0.082R   t=-0.69
  clamp ≥0.8%   每筆差 -0.113R   t=-0.99
  （8 個變體 |t| 全部 < 1，符號混雜）
```

樣本翻 4 倍，最強的變體從 t=2.59 掉到 t=-0.02 **且符號翻面**。這是雜訊的典型形狀，
跟 2026-09-03 那次 TP 位置（n=200 t=3.41 → n=705 t=2.13）同一種，只是這次更徹底。

### ⚠ `n=1473` 是假的樣本量

三組報表（全部 / 只看 B / 只看 B 且 < 1.0%）的 t 值**完全相同**：

```
0.57  0.14  -0.02  -0.39  -0.4  -0.69  -0.65  -0.99
```

因為止損距離本來就在下限之上的訊號，兩個政策結果完全一樣，對成對差異貢獻 0。
它們同時放大 n 與縮小 sd，t 不受影響但**看起來像大樣本**。實際受影響的是
22–77 筆，全部落在策略 B。腳本現在會印「受影響 N/總數」。

**檢定力**：受影響那群 sd ≈ 0.96。要偵測 +0.061R/筆（最好的變體）需要
受影響訊號 n ≈ 990，目前 22 筆。差了 45 倍。

### 為什麼測不出來——機制上說得通

代價大於好處。以 `clamp ≥1.0%` 為例，受影響的 77 筆平均止損距離約 0.5%：

```
手續費省下   0.12R → 0.06R    = +0.06R
止損推遠代價 每筆差 -0.082R
```

省下的手續費被 R 分母變大與訊號減少吃光還倒賠。**這不是「下限沒用」，是
「這個修法的淨效果在雜訊裡」。**

## 5. 真正該處理的是另一個東西：倉位公式繞過了自己的設計意圖

`calcPositionPlan`（`position.ts:47-53`）：

```ts
const positionUSDT = riskUSDT / stopDist;          // 沒有上限
const marginBudget = accountSize * 0.2;            // 設計意圖：每筆本金 20% 帳戶
let leverage = positionUSDT / marginBudget;
leverage = Math.min(Math.max(leverage, 1), maxLev); // 槓桿夾到 [1, 10]
const marginUSDT = positionUSDT / leverage;         // ← 用夾過的槓桿反推本金
```

**槓桿被夾住，名目沒有。** `positionUSDT` 超過 `marginBudget × maxLev` 時，
程式不是縮小倉位，而是放大本金。實測（帳戶 4,847 USDT，風險 1%）：

```
止損距離     名目倉位      本金       佔帳戶    槓桿
  0.103%     47059.2U    4705.9U     97.1%    10.0x   ← 單筆吃掉 97% 帳戶
  0.250%     19388.4U    1938.8U     40.0%    10.0x
  0.500%      9694.2U     969.4U     20.0%    10.0x   ← 設計意圖，槓桿剛好頂到 10
  1.000%      4847.1U     969.4U     20.0%     5.0x
  2.000%      2423.5U     969.4U     20.0%     2.5x
```

**止損距離 ≤ 0.5% 時「每筆本金 20%」就失效了**，因為槓桿已經頂到上限，
再小的止損距離只能靠放大本金來維持名目。

那筆 BTC 是 tier B（`tierRiskMultiplier` = 0.5）所以風險 0.5%，名目 19,767U、
本金約 1,977U = **帳戶的 40.8%**，設計意圖的兩倍。

### 為什麼既有的風控全都攔不到

- **R 上限**（`MAX_DRAWDOWN_R`、熔斷、`MAX_TOTAL_RISK_PCT`）看不到：名目 19,767U
  的部位「就是 1R 風險」，每一道 R 上限都沒有被違反。這正是 `dailyLossCap.ts`
  檔頭寫的「帳戶可以在完全沒有違反任何 R 上限的情況下被打穿」。
- **`checkLiquidationSafety`** 看不到：它檢查「止損比強平先觸發」。槓桿 10 倍時
  強平距離約 10%，止損 0.103% 確實先到，**這道檢查會通過**。
- **`MAX_TOTAL_RISK_PCT`** 看不到：它加總的是 `suggested_risk_pct`，跟名目無關。

### 建議的修法方向

夾住名目（或等價地夾住本金佔比），超過就縮小倉位。這件事**跟策略參數無關**：

- 不改變任何訊號的進出場位置，訊號集合完全不變
- 不改變 R 倍數，所有既有 R 統計不受影響
- 只改變「這一筆願意押多少錢」

也就是說它不受 CLAUDE.md §4「不要調參」約束——那條約束的是會改變訊號集合或
R 分布的東西。這個只改絕對金額。

副作用要講清楚：夾住名目之後，止損很近的單實際承擔的風險金額會**低於**設定的
風險%（例如設 1% 實際只押 0.4%）。那是刻意的——止損距離小到需要 97% 帳戶保證金
才能湊出「1% 風險」時，正確答案是少押一點，不是照押。

## 6. 沒有回答的問題

- **策略 B 到底有沒有邊際**：n=99（模擬）／13（真倉），`|t| < 1`，測不出來。
  跟整個專案其他層面的結論一致。
- **0.06% 費率會不會低估**：全 taker 進出是 0.08%，模型用實測的 0.06%（偏保守，
  低估成本）。改用 0.08% 會讓所有下限變體看起來更好一點，但差距遠小於雜訊。
- **名目暴增的二階效應完全沒模擬**：大單的實際滑價、保證金占用擠掉其他訊號
  （跟 2026-08-20 那次全局風險上限卡死同形狀）。模型用固定滑價，這些都算不到。
  **這是第 5 節那個問題被低估而不是高估的理由。**

## 1. 背景

這是一套加密貨幣永續合約的多策略自動交易系統，目前包含：

- **策略 A：趨勢追蹤**（EMA / Donchian）
- **策略 B：均值回歸**（Bollinger / RSI）
- **策略 C：資金費率情緒**
- 共用層：ADX 盤勢過濾、BTC 大盤過濾、信心分數（confidence scoring）、分層風控、訂單狀態機、獲利保護階梯

**目前的症狀：** 策略不是訊號太少，就是勝率不夠，整體無法獲利。

**實盤曾出現的問題（請逐項確認現況是否已修復）：**

1. 多張高度相關的多單同時進場、同時停損
2. 濾網過嚴導致完全沒有訊號
3. 疑似部位大小（position sizing）計算錯誤
4. 策略 B 的分數閘門可被繞過
5. 訂單逾時取消後，立刻反向下單

---

## 2. 目標與成功定義

**目標不是「提高勝率」，而是讓「扣除所有成本後的每筆期望值」為正，且在樣本外仍成立。**

```
每筆期望值 = 勝率 × 平均獲利 − 敗率 × 平均虧損 − 成本
成本 = 手續費（進出各一次）+ 滑價 + 資金費
```

本任務的成功定義有兩種，兩種都算完成：

- **A. 找到並驗證 edge**：至少一個策略（或組合）通過第 9 節的上線閘門。
- **B. 誠實證明沒有 edge**：以證據說明哪些策略在扣成本後期望值 ≤ 0，並提出下一步研究方向。

**不接受的結果：** 靠調參數把回測曲線調漂亮，卻沒有樣本外驗證。

## 3. 硬性規則

1. **整個任務期間不得下任何實盤單**，不得修改實盤設定或正在運行的部署，除非我明確同意。
2. 所有修改都在獨立分支進行，每個修復附上對應的測試。
3. 不得為了讓回測變好而新增參數。每新增一個參數或濾網，都必須附樣本外的證據。
4. 不得使用未來資訊：訊號只能用已收盤的 K 棒，成交以下一根 K 棒開盤價（加滑價）計算。
5. 測試期資料（見 6.3）在整個研究過程只能用一次，用來做最終驗證，不能拿來調參。
6. 報告中的每個結論都要附數字與可重現的指令，不要只給定性描述。
7. 遇到與本文件描述不符的程式現況，以程式為準並回報差異。

## 5. Phase 1：正確性稽核

在討論策略好壞之前，先確認程式做的事和規格一致。產出 `reports/01_correctness.md`，每項標明「正常 / 有問題 / 無法確認」，有問題者附重現方式。

### 5.1 訊號與資料

- [ ] 是否用到未收盤 K 棒或未來資料（look-ahead）
- [ ] 指標暖機期是否足夠，暖機期間是否會誤發訊號
- [ ] 多時框對齊是否正確（高時框的值是否在收盤後才可見）
- [ ] 時區、時間戳、K 棒缺漏的處理
- [ ] 資金費率的時間點與正負號方向

### 5.2 部位與風控

- [ ] 部位大小 = 風險金額 ÷ 停損距離，是否正確處理合約面值、槓桿、最小下單量、數量精度
- [ ] 實際下單量與計算量是否一致（比對實盤紀錄）
- [ ] 停損、停利是否真的掛到交易所，還是只在本地監控
- [ ] 組合層是否有總曝險與同方向部位數上限
- [ ] 單日虧損上限與 kill switch 是否存在且可觸發

### 5.3 訂單生命週期

- [ ] 狀態機所有狀態與轉移是否完整（含部分成交、取消失敗、重複回報）
- [ ] 逾時取消後是否仍可能立刻反向下單
- [ ] 重啟或斷線後能否與交易所對帳、還原部位與掛單
- [ ] 是否可能重複下單（冪等性）

### 5.4 策略邏輯

- [ ] 策略 B 的分數閘門是否仍可被繞過
- [ ] 各濾網的實際通過率（見 Phase 3 的漏斗分析）
- [ ] 策略之間是否會互相打架（同幣種一多一空、互相平倉）
- [ ] 進場與反轉是否有遲滯、冷卻時間，是否會在短時間內來回翻單（見第 13 節）

### 5.5 交易所設定與帳戶安全

- [ ] API key 只開交易權限，**關閉提幣權限**，並綁定 IP 白名單
- [ ] 金鑰不出現在 repo、日誌、錯誤訊息、前端程式中；用環境變數或 secret 管理
- [ ] 使用獨立子帳戶，與手動交易的資金隔離
- [ ] 保證金模式（逐倉 / 全倉）、持倉模式（單向 / 雙向）、槓桿倍數是否由程式在啟動時明確設定並驗證，而不是依賴帳戶當下的狀態
- [ ] 停損的觸發價是標記價格還是最新成交價，是否與回測假設一致
- [ ] 停損價是否一定在強平價之前觸發，兩者距離是否足夠
- [ ] API 速率限制、錯誤碼、交易所維護時段的處理
- [ ] 幣種下架、合約規格變更（最小下單量、tick）時的處理

### 5.6 基礎設施與維運

- [ ] 主機時間同步（NTP），並檢查與交易所伺服器的時間差
- [ ] WebSocket 斷線重連；偵測到行情過期（stale data）時不得下單
- [ ] 程序監管與自動重啟；重啟後先對帳，再恢復交易
- [ ] 程式失聯時，交易所端仍有停損單保護（不能只靠本地監控）
- [ ] 告警通道（例如 Telegram）：下單、錯誤、對帳差異、kill switch 觸發
- [ ] 結構化日誌：每筆決策都能回溯當時的指標值、濾網結果、分數、下單參數
- [ ] 設定檔有版本控管，有部署與回滾流程
- [ ] 有手動緊急全平倉並停止交易的指令

確認為 bug 的項目，修復並附測試後，再進下一個 Phase。

## 6. Phase 2：回測基礎建設

若現有回測不符合下列要求，請補齊。產出 `reports/02_backtest_spec.md`，說明每項假設。

### 6.1 必須涵蓋的成本與限制

- 手續費：用第 0 節的實際費率，進出各一次
- 滑價：市價單至少 1–2 個 tick 或固定 bps，停損單用更保守的值
- 資金費：持倉跨結算時間點時依歷史費率計算
- 最小下單量、價格與數量精度
- K 棒內同時碰到停損與停利時，**一律假設先碰停損**
- 停損在急跌急漲時的成交價會比觸發價差，停損滑價要另外用更保守的假設
- 限價單（含 post-only）要模擬「未成交」的情況，不能假設掛了就成交（見第 15 節）
- 流動性限制：單筆下單量不得超過該幣種當時成交量或深度的合理比例
- 槓桿與強平：回測中若價格觸及強平價，該筆以強平計算

### 6.2 資料

- 至少 24 個月歷史資料，需涵蓋上漲、下跌、盤整三種盤勢
- 包含 K 線、資金費率；可取得的話加上未平倉量（OI）
- 注意倖存者偏誤：幣種清單應以「當時可交易」為準，不是只用現在還活著的幣

### 6.3 資料切分

- 訓練期：最早的 60%
- 驗證期：中間 20%（可用於挑選參數）
- 測試期：最後 20%（**只能用一次**）
- 另做 walk-forward：滾動視窗重新估參數，再在下一段評估

### 6.4 一致性檢查

- 把實盤運行過的期間丟進回測，逐筆比對訊號與成交。
- 若回測與實盤的訊號不一致，先修到一致，否則後面所有回測數字都不可信。

## 7. Phase 3：逐策略期望值診斷

**每個子策略單獨回測，不要先看組合。** 產出 `reports/03_strategy_diagnosis.md`。

### 7.1 每個策略要回報的指標（訓練期、驗證期分開列）

| 指標 | 說明 |
|---|---|
| 交易筆數 | 少於 100 筆請標註「樣本不足」 |
| 勝率 | |
| 平均獲利 / 平均虧損 | 以 R（風險倍數）與 % 表示 |
| 盈虧比 | |
| 每筆期望值（毛） | 未扣成本 |
| 每筆期望值（淨） | 扣除全部成本 |
| 成本佔毛利比例 | 超過 50% 即為成本問題 |
| Profit factor | |
| 最大回撤、最長連虧 | |
| 平均持倉時間 | |

### 7.2 拆解分析

- 依幣種、多空方向、盤勢（ADX 高低、BTC 漲跌）、出場原因分組
- **濾網漏斗**：原始訊號數 → 每一層濾網後剩餘數 → 最終下單數
- **濾網消融**：逐一關閉每個濾網，比較樣本外期望值。只保留能改善樣本外期望值的濾網。
- **成本敏感度**：成本假設 ×1、×1.5、×2 時期望值是否仍為正
- **參數穩定性**：主要參數上下調整 20%，結果是否大致相同（孤峰代表過度擬合）
- **實驗紀錄**：記錄總共試過幾組參數與幾個版本（見第 16 節的多重檢定）
- **回撤分布**：用蒙地卡羅重排交易順序，估計回撤的分布，而不只看單一條歷史曲線

### 7.3 診斷結論對照表

每個策略必須歸入下列其中一類：

| 現象 | 判定 | 處置方向 |
|---|---|---|
| 毛期望值 ≤ 0 | 沒有 edge | 不要調參，擱置或換邏輯 |
| 毛 > 0，淨 ≤ 0 | 被成本吃掉 | 拉長時框、改用限價單、放大目標、減少交易 |
| 淨 > 0，但筆數太少 | 頻率問題 | 擴大幣種與時框，**不要放寬進場條件** |
| 訓練期好、驗證期差 | 過度擬合 | 減少參數與濾網 |
| 淨 > 0 且穩定 | 候選策略 | 進入 Phase 4 |

## 13. 策略設計原則：避免被來回洗

「做多後盤面突然轉空」多數是短時框的雜訊，不是可以預測的轉折。目標不是判斷得更快，而是讓系統在看錯時損失很小、不被雜訊牽著走。

- **時框**：訊號時框以 4h 或日線為主。秒到分鐘級是造市商與高頻的領域，延遲與手續費都比不過。若要用短時框，必須證明扣成本後仍有 edge。
- **遲滯**：進場門檻與反轉門檻要不同，避免在臨界值附近反覆進出。
- **冷卻時間**：停損或平倉後，同幣種同策略在一段時間內不得再進場。
- **不立即反手**：停損不等於反向訊號。反向進場必須獨立滿足完整的進場條件。
- **最短持倉時間 / 最少 K 棒數**：除了停損以外，不因單根 K 棒的變化就出場。
- **小部位**：單筆風險小到「連錯十筆也不影響系統繼續運作」。
- **確定性**：相同輸入必須產生相同決策。即時決策流程中不放 LLM 或其他不可重現的元件，原因有三：延遲高、結果不穩定、而且無法誠實回測（模型可能已經知道歷史結果，等於偷看未來）。
- **盤勢辨識的用途是「決定要不要交易」**，不是用來頻繁切換多空方向。看不清楚時的正確動作是不交易。

## 14. 消息面與事件風險

消息面用於**防守**，不用於搶方向。價格在幾秒內就反應完畢，程式讀到消息再下單通常已經是追價。

### 14.1 排程事件

- 維護一份事件行事曆：CPI、FOMC、非農、重大代幣解鎖、交易所公告等
- 事件前後的固定時間窗內：降低部位、暫停開新倉，或收緊停損（三選一，由回測決定哪個較好）

### 14.2 斷路器（不需要知道消息內容，只看市場反應）

符合任一條件即暫停開新倉，並發出告警：

- 短時間波動率超過近期平均的數倍
- 買賣價差異常放大
- 資金費率到達極端值
- 價格在短時間內跳動超過設定門檻
- 行情資料中斷或延遲

### 14.3 尾部事件

以下情況發生時的處置要事先寫好，不要臨時決定：

- 閃崩與連環清算（此時所有幣種相關性趨近 1，分散失效）
- 穩定幣脫鉤（USDT 本位合約的保證金價值會受影響）
- 交易所暫停出金、API 中斷、系統維護
- 交易所自動減倉（ADL）或強制平倉

---

## 15. 執行品質與流動性

- **流動性濾網**：幣種須符合最低 24h 成交量與最大價差門檻，才列入可交易清單。清單要定期重新檢查。
- **下單量上限**：單筆不超過訂單簿前幾檔深度的合理比例，避免自己推動價格。
- **限價單的陷阱**：post-only 可省手續費，但會有逆選擇：價格往有利方向走時不成交，往不利方向走時才成交。回測必須模擬這件事，否則限價單的績效會被嚴重高估。
- **實測滑價回饋**：實盤每筆記錄「預期價 vs 成交價」，定期用實測值更新回測的滑價假設。
- **資金費結算**：結算時間點前後的進出場，要把資金費算進該筆損益。
- **低流動性時段**：週末與亞洲深夜的價差與滑價通常較大，回測要分時段檢查績效。
- **標記價格 vs 最新價**：停損觸發依據要明確，並與回測一致。

---

## 16. 統計陷阱

- **多重檢定**：試的參數組合越多，越可能純靠運氣得到漂亮的回測。必須記錄總實驗次數，試得越多，上線門檻就要越高。
- **樣本不獨立**：多個相關幣種同時進場的交易，統計上接近同一筆。評估樣本數時要以「獨立的進場時點」計算，不是以下單筆數計算。
- **盤勢依賴**：只在單一盤勢（例如牛市）有效的策略，要明確標示，並確認盤勢過濾在樣本外真的有用。
- **回測期間選擇**：不得因為某段期間績效不好就把它排除。
- **績效來源集中**：若大部分獲利來自少數幾筆或單一幣種，移除後重測，確認結果是否仍成立。
- **Edge 衰退**：有效的策略也會隨時間失效，上線後要持續與回測分布比對（見第 17 節）。
- **複利與破產風險**：用回撤分布檢查，在預期的連虧情況下帳戶是否仍能存活。

## 17. 上線後的維運與停機準則

停機條件要在上線**之前**寫好，避免事後找理由繼續跑。

### 17.1 自動停機條件（預設值，可調整）

- 實盤回撤超過回測最大回撤的 1.5 倍
- 最近 N 筆交易的期望值低於回測分布的第 5 百分位
- 實測滑價或成本持續高於回測假設的 2 倍
- 回測與實盤的訊號不一致
- 對帳出現無法解釋的差異

### 17.2 人為紀律

- 系統運行期間不手動干預個別交易。若有干預，必須記錄原因，且該筆不計入系統績效。
- 上線後任何參數或邏輯變更，都要重跑第 9 節的驗證流程，不得直接改實盤。
- 每季重新驗證一次：用新增的資料當樣本外，檢查 edge 是否仍在。

### 17.3 資金與帳務

- 只投入賠光也不影響生活的資金。
- 交易所帳戶只放必要的保證金，其餘資金不留在交易所（交易對手風險）。
- 槓桿設上限，實際使用槓桿由部位大小公式決定，不是由「想賺多少」決定。
- 保存完整的交易、資金費與手續費紀錄，供績效檢討與報稅使用。稅務規定請另行確認。

## 附錄 A：候選研究方向

以下都只是有結構性理由、值得回測的方向，**未經驗證，近年報酬也普遍被壓縮**，一樣要通過第 9 節的上線閘門。

| 方向 | 邏輯 | 主要風險 / 失效情境 | 額外需求 |
|---|---|---|---|
| 跨多幣趨勢追蹤（4h / 日線）+ 波動率調整部位 | 靠少數大行情獲利，勝率低、盈虧比高 | 長時間盤整會連續小虧；幣種高度相關 | 多幣種歷史資料 |
| 橫截面動能（多強空弱） | 方向接近中性，不需判斷大盤多空 | 急反轉時多空兩邊同時虧損；弱勢幣流動性差、空單資金費高 | 幣種池要夠大且流動性足夠 |
| 資金費率 / 基差 carry（現貨多 + 永續空） | 收取資金費，報酬來源明確 | 費率轉負、交易所風險、兩邊保證金管理 | 需要現貨帳戶與資金 |
| 清算與未平倉量事件後的均值回歸 | 大量爆倉後的過度延伸常回彈 | 接刀風險、執行延遲、需要嚴格停損 | OI 與清算資料，執行要求最高 |

研究任何新方向時，同樣遵守：先寫下假設與預期，再回測；不因結果不好就反覆修改到通過。
